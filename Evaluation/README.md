# Evaluation Folder — Project Data Hub

This folder is the **consolidated project data hub** for the Liver CT Segmentation project. It was generated by analysing all 150+ markdown documentation files and machine-readable data artifacts (JSON/YAML/CSV) across the repository and compiling every dataset value required to understand, reproduce, and evaluate the project.

## Contents

| File | Description |

## Notebook suite — Mark 1 → Mark 4E (runnable reproduction)

The original eight research notebooks in `mark 1/` are reproduced here as **eleven ordered, self-contained
notebooks** (the earlier single mega-notebook attempt is archived under
`_archive_single_notebook_attempt/`). Each notebook answers one research question, embeds the *identical*
shared global-setup cell (paths, seeds, provenance hashes, test lock, helpers), and writes into the same
organized output root — so results are directly comparable to the archived `mark 1/mark_*_outputs/` runs.
Notebook 11 is a light maintenance step (not part of the research loop): it re-scans `output/` and rebuilds
`artifact_index.json` into a complete SHA-256 manifest, so the registry covers data CSVs/JSONs, `.npz`
caches and `.pth` checkpoints in addition to figures.

Each notebook writes into its own sub-folder split into `data/` (CSV + JSON), `figures/` (all PNGs incl. the
standardized `<phase>_summary_dashboard.png`), and `caches/` (expensive `.npz` probability caches). Naming is
uniform: `<phase>_gate_result.json` (machine-readable gate), `<phase>_history.csv` (training history),
`*_metrics.csv` (patient/slice tables), `<theme>_<name>.png` (visualizations).

`artifact_index.json` is maintained as a **complete SHA-256 manifest** of every file under `output/`
(data, figures, caches, checkpoints) by notebook 11, which scans the tree deterministically. It is
versioned (`version: 2` for the complete-manifest format) and self-verifying via
`11_artifact_registry/registry_verification.json`.

The shared setup cell in every notebook defines availability-check helpers: `load_shared(phase, name)` reuses
an artifact if it exists in `output/<phase>/data/` (the canonical source — the legacy
`mark_1_to_4e_outputs/` mirror was removed during the 2026-08 reorganization; its contents are
preserved in `backup/05_outputs_legacy_mirror.zip`), otherwise raises a clear
"run the upstream notebook first" error. `require_upstream_gate("mark_X")` is how phases 02–09 read the
previous phase's gate. `save_figure/save_table/save_json` write into the current notebook's sub-folder and
register the artifact in `artifact_index.json`.

### How to run (manually)

1. Open `00_pipeline_overview_and_setup.ipynb` — select the **Python (.venv)** kernel — then `Run All`.
2. Run notebooks `01 → 09` in order — phases 02–09 read the previous phase's gate JSON from the shared
   output folder, so the order is a real dependency (a phase can be re-run standalone once its upstream
gates exist). Each notebook embeds the shared setup cell, so it is self-contained.
3. (Optional) Run `10_unified_data_visualization.ipynb` for the combined visualization hub, and
   `11_artifact_registry_consolidation.ipynb` to rebuild the complete artifact SHA-256 manifest.
3. **REUSE mode (default):** reads frozen caches/checkpoints from `mark 1/` → fast, deterministic, and the
   gate JSONs reproduce the originals exactly (each phase asserts drift < 1e-4 against `mark 1/mark_*_outputs/`).
4. To rebuild caches or retrain, flip the `REUSE_*` / `RUN_*` flags in the shared setup cell (GPU hours).

Every notebook opens with a **mermaid dataflow diagram** (inputs → phase cells → gate/outputs; notebook 00
adds the full `00 → 09` pipeline flow) plus a per-phase visualization list, so each notebook is self-documenting.

The test split stays locked in every notebook.

### Notes on structure

The Evaluation folder intentionally keeps only **markdown (`.md`) and notebook (`.ipynb`) files** plus the
generated output data under `Evaluation/output/`. The legacy `mark_1_to_4e_outputs/` folder from the previous
layout was removed during the 2026-08 reorganization — `output/` is now the single canonical source, and the
removed mirror is preserved in `backup/05_outputs_legacy_mirror.zip`. The `.py` generator sources used to build
the notebooks have been removed; the notebooks are fully self-contained and are the edited-in-place artifacts
going forward. The superseded single-notebook attempt lives in `_archive_single_notebook_attempt/` (kept as a
historical reference, also as md + ipynb only).
