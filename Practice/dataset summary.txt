1. DECISION AND TECHNICAL SUMMARY
---------------------------------

Training is currently BLOCKED.

The dataset has complete numerical filename coverage, but only part of the
image-mask collection can be proven locally to originate from the same source
payload. The legacy 512x512 image collection is not safely interchangeable
with the 256x256 lits-png image collection. A successful count-based join of
58,638 images and masks is therefore insufficient evidence for segmentation.

The preferred resolution is to reconstruct all image, liver-mask, and
tumor-mask slices from one authoritative source. The strongest option is the
official LiTS NIfTI volumes and segmentations. The fallback is a complete,
fresh extraction of the same lits-png package containing the image, liver mask,
and lesion mask for every slice.

After reconstruction, build a versioned canonical dataset, generate a complete
slice manifest and checksums, perform automatic and visual spatial validation,
lock volume-wise splits, run a small overfit sanity test, and only then return
to the staged 5-to-10-epoch research protocol.

4. DATA QUALITY RISKS AND SEVERITY
----------------------------------

CRITICAL: Training on unproven spatial pairs

Matching counts and filenames do not prove the mask belongs to the displayed
CT slice. A segmentation model trained on misregistered masks will learn noise,
produce extremely low Dice, and make every architecture/loss comparison
meaningless.

HIGH: Incomplete same-package mask extraction

Only 15,817 lesion masks and 15,868 liver masks remain beside the complete
58,638 candidate images. The missing source masks prevent complete local
pixel-level provenance verification.

HIGH: Legacy and candidate images are not interchangeable

The 512x512 legacy images and 256x256 candidate images share numerical keys but
do not have sufficiently similar image content to be treated as alternative
preprocessing versions without additional provenance proof.

HIGH: Invalid CSV key choice

Using study_number plus instance_number creates 30,105 duplicate keys because
instance_number wraps at 256.

MEDIUM: Misleading empty-mask field name

The tumor_mask_empty field means tumor present. This can silently invert label
logic in analysis, sampling, or training.

MEDIUM: Incomplete upstream train/test CSVs

The supplied CSV splits omit 29.12% of the dataset and duplicate test as probe.

MEDIUM: Masks stored as RGB values 0/1

The masks are valid, but they appear nearly black in ordinary image viewers.
Canonical derived masks should be documented and may be stored as 0/255 for
easy inspection while being converted to binary 0/1 tensors in memory.


5. AUTHORITATIVE SOURCE STRATEGY
--------------------------------

Use the following preference order.

Option A - preferred:

Obtain the official LiTS NIfTI volumes and matching segmentation NIfTI files.
Each CT and segmentation pair must come from the same release and preserve:

- volume identity
- voxel spacing
- affine/orientation metadata
- slice ordering
- original segmentation labels

For official LiTS labels, normally derive:

- background: label 0
- liver region: labels 1 and 2
- tumor region: label 2

Confirm the source label definition before conversion rather than relying only
on this expectation.

Option B - acceptable fallback:

Re-download or re-extract the complete lits-png package so that every filepath
listed in lits_df.csv is present together:

- volume-{v}_{s}.png
- segmentation-{v}_livermask_{s}.png
- segmentation-{v}_lesionmask_{s}.png

Do not merge images from one PNG source with masks from a separately converted
source merely because volume and slice numbers look identical.

Option C - temporary audit only:

Use the existing 15,817 same-source triples to verify conversion code and build
tests. Do not use this biased 25-volume subset for final baseline comparison,
validation, or held-out evaluation.

10. MISSING-DATA AND EXCLUSION POLICY
-------------------------------------

10.1 Valid empty tumor mask

Definition:
A tumor-mask file exists, is readable, has correct geometry, and contains zero
positive pixels.

Action:
Keep it. This is a valid negative training/evaluation slice.


10.2 Missing tumor-mask file

Definition:
The expected tumor-mask file is absent.

Action:

- Mark excluded_missing_tumor_mask.
- Add the key and reason to missing_data.csv.
- Do not create an empty mask.
- Do not include in training, validation, or test.
- Prefer blocking the entire canonical build until the authoritative source is
  recovered.


10.3 Missing liver-mask file

Action:

- Mark excluded_missing_liver_mask.
- Do not use the slice for tumor training because spatial containment cannot be
  validated under this workflow.
- Recover the correct source rather than copying a neighboring mask.


10.4 Missing image file

Action:

- Mark excluded_missing_image.
- Do not retain orphan masks as training samples.
- Investigate archive/extraction completeness.


10.5 Corrupt or unreadable files

Action:

- Record original path, checksum if readable, exception, and key.
- Copy to 99_quarantine only after source registry/checksum capture.
- Re-extract from the authoritative archive.
- Do not repair pixels manually.


10.6 Duplicate key

Action:

- Compare checksums and provenance.
- Identical duplicates: retain one canonical record and document all aliases.
- Different-content duplicates: block the volume until source lineage resolves
  which record is authoritative.
- Never choose the newest file automatically.


10.7 Geometry mismatch

Action:

- Stop processing that volume.
- Compare affine, spacing, orientation, dimensions, and slice count.
- Re-export image and masks together.
- Do not independently resize or rotate only the mask.


10.8 Outlier masks

Large, tiny, fragmented, or multifocal masks are not automatically errors.
Flag them for review using robust volume/slice distributions. Exclude only when
there is documented corruption or misregistration.


11. CANONICAL PREPROCESSING POLICY
----------------------------------

11.1 If source is official NIfTI

- Preserve original NIfTI files unchanged.
- Record spacing, affine, orientation, and intensity units.
- Apply any canonical orientation to image and segmentation together.
- Derive a documented 256x256 training representation.
- If an HU window is used, define it explicitly and store it in the conversion
  profile.
- Never overwrite raw NIfTI data with windowed arrays.

11.2 If source is PNG

- Treat PNG intensities as already windowed display values.
- Do not apply simulated HU conversion.
- Do not claim that 0-255 PNG values are calibrated Hounsfield units.
- Use grayscale 256x256 training images.
- Keep no-HU and no-CLAHE as the initial canonical baseline profile.

11.3 Mask handling

- Use nearest-neighbour interpolation only.
- Store masks losslessly.
- Recommended on-disk derived representation: uint8 values 0 and 255.
- Convert to float/binary 0 and 1 in memory.
- Threshold source 0/1 masks using value greater than zero.
- Never use bilinear or bicubic interpolation for labels.

11.4 Training-time augmentation

Apply only to training data and synchronously to image and mask:

- horizontal flip
- intensity shift plus/minus 0.1 on image only

Do not augment validation or test data.

- Train volumes: 0 through 103

- Test volumes: 117 through 130

13. DATA LOADER REQUIREMENTS
----------------------------

The canonical data loader must consume slice_manifest.csv or split-specific
slice CSVs rather than globbing unrelated folders and replacing filename
prefixes.

Required loader behavior:

- Read only verification_status=verified rows.
- Enforce the requested split.
- Assert image, liver mask, and tumor mask exist.
- Assert matching sample IDs and geometry.
- Load grayscale image as one channel.
- Convert tumor mask to binary using value greater than zero.
- Optionally load liver mask for QA or liver-aware sampling.
- Do not apply HU transformation to already windowed PNGs.
- Resize labels with nearest-neighbour only.
- Apply synchronized spatial augmentation.
- Return volume_id, slice_index, and sample_id for evaluation aggregation.
- Fail loudly on missing or duplicate samples.
- Never silently skip a broken row.

Required tests:

- filename and manifest parsing
- instance_number wrap regression
- unique primary keys
- missing file behavior
- valid empty masks
- binary conversion for masks stored as 0/1 and 0/255
- image/mask alignment after resizing
- synchronized augmentation
- train/validation/test isolation
- deterministic seed behavior
- per-volume grouping

16. TRAINING PROMOTION ORDER AFTER DATASET APPROVAL
---------------------------------------------------

Gate 1 - small overfit sanity

- Select 16 verified tumor-positive slices from training volumes only.
- Use the canonical MobileNetV2-U-Net and Focal-Dice implementation.
- Require training micro Dice of at least 0.80.
- Inspect predictions visually.
- Failure means loader, label, loss, normalization, or architecture debugging.
- Do not proceed to full training after an overfit failure.

Gate 2 - synthetic integration smoke test

- One epoch
- Checkpoint save/reload
- Deterministic evaluation
- Report generation
- Resume behavior

Gate 3 - corrected baseline through epoch 5

- MobileNetV2-U-Net with pretrained encoder
- 256x256 grayscale
- verified tumor masks
- no simulated HU transformation
- no CLAHE
- Focal-Dice alpha 0.75, gamma 2.0
- tumor-positive sampler weight 3
- batch size 4
- mixed precision
- zero DataLoader workers
- seed 42
- horizontal flip and intensity shift on training only
- select best checkpoint using validation positive-volume Dice

Gate 4 - validation promotion

Promote to epoch 10 only if validation evidence is credible and improving. Use
the previously defined baseline sanity criteria:

- AUPRC greater than at least 2 times foreground prevalence
- positive-slice Dice greater than 0.10
- precision greater than 0.10
- recall not zero and not effectively one
- predicted foreground fraction between 0.25 and 4 times true fraction

Gate 5 - controlled candidate comparison

Only after the corrected baseline passes:

- MobileNetV2-U-Net plus Focal-Dice
- FAUP-Net plus Focal-Dice
- FAUP-Net plus UWACL-v2

Keep data, augmentation, seed, epoch target, checkpoint selection, and threshold
selection identical.

Gate 6 - one-time held-out test

Evaluate each locked promoted model once. Do not use test outcomes to modify the
threshold, loss, sampler, preprocessing, or architecture.
